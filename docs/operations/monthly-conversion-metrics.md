# 홈페이지 전환성과 월별 운영 기준

## 목적

개인정보를 추가로 저장하지 않고 `careerservice.co.kr` 방문이 서비스 이해, 문의, 신청으로 이어지는 흐름을 월 단위로 확인한다.

## 기본 원칙

- Cloudflare Web Analytics의 집계형 방문 통계를 우선 사용한다.
- 이름, 이메일, 전화번호, 상담내용과 방문기록을 결합하지 않는다.
- 광고 픽셀이나 방문자별 프로파일링을 사용하지 않는다.
- 실제 상담신청 수는 Cloudflare Worker의 정상 접수와 담당자 Telegram 알림을 운영기록으로 확인한다.
- 초기에는 별도의 세부 클릭 추적 스크립트를 추가하지 않는다.

## 월별 핵심지표 6개

1. 전체 방문자 수
2. `/business-consulting/` 방문 수
3. `/career-planning/` 방문 수
4. `/contact/` 방문 수
5. 신청서 다운로드 수
6. 실제 상담신청 수

## 해석 기준

- 전체 방문 대비 서비스 페이지 방문이 낮으면 홈의 대상별 진입 구조를 점검한다.
- 서비스 페이지 방문 대비 문의 페이지 방문이 낮으면 대상·혜택·절차·CTA 문구를 점검한다.
- 커리어플래닝 페이지 방문 대비 다운로드가 낮으면 신청요건과 서류 안내를 점검한다.
- 문의 페이지 방문 대비 실제 접수가 낮으면 입력 부담, 개인정보 안내, 오류·대체경로를 점검한다.
- 방문량이 적을 때는 단기 비율로 성급하게 결론 내리지 않고 최소 월 단위 추세를 본다.

## 지표 확보 방법

- 1~4번: Cloudflare Web Analytics의 페이지별 방문 통계
- 5번: 기본 Analytics에서 파일 URL 확인이 충분하지 않을 경우 2단계 이벤트 구조로 별도 설계
- 6번: Worker 정상 응답 및 실제 Telegram 접수 운영기록

## 월별 보고 형식

- 기준월
- 전체 방문자
- 기업컨설팅 페이지 방문
- 커리어플래닝 페이지 방문
- 문의 페이지 방문
- 신청서 다운로드
- 실제 상담신청
- 전월 대비 변동
- 확인된 사실
- 개선 필요사항
- 다음 달 조치

## 2단계 전환 조건

다음 중 하나가 확인되면 세부 이벤트 추적을 별도로 검토한다.

- 다운로드 수를 기본 Analytics에서 신뢰성 있게 확인하기 어려움
- 문의 페이지 방문은 많으나 실제 접수가 계속 낮음
- 기업·개인 CTA별 성과를 분리해야 함
- 정책소식별 상담 유입을 판단해야 함

2단계에서도 개인정보·상담내용·사용자 식별자를 이벤트에 포함하지 않는다.
